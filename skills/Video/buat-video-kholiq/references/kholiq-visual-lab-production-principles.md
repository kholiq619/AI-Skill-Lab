# Kholiq Visual Lab — Production Principles

This reference supports the `/buat-video` execution workflow. It is a concise companion guide, not a replacement for any separate Kholiq Visual Lab Skill the user has enabled.

## Creative direction
- Design for the actual story and audience; do not force every video into the same template.
- Establish a clear visual hook immediately.
- Vary scene duration, camera movement, transitions, scale, and visual rhythm according to the content.
- Use easing, stagger, overshoot, parallax, depth, and purposeful camera movement where they improve clarity.
- Keep motion smooth and intentional. Avoid motion for motion's sake.
- Maintain visual consistency in typography, palette, illustration style, lighting, and recurring subjects.

## Composition and readability
- Design for mobile-first viewing.
- Keep important text and subjects inside platform-safe areas.
- Use strong contrast and readable type sizes.
- Avoid text collisions, clipped edges, excessive grain, and motion blur that harms legibility.
- Make labels and numerical claims unambiguous; include units and source context when relevant.

## Sound
- Synchronize important visual events with sound cues.
- Use layered impacts only where they strengthen a meaningful moment.
- Duck music under narration.
- Do not use copyrighted music or sound effects without permission or an appropriate license.
- Do not invent credits or claim a license was checked when it was not.

## Rendering and quality control
- Render a draft when practical, inspect key frames, correct defects, then render the final.
- Inspect the actual final MP4, not only source stills.
- Verify file integrity, duration, dimensions, frame rate, and audio presence.
- Ensure captions follow the voiceover and remain readable.
- If the render fails or is interrupted, report the precise status and resume from saved work rather than claiming completion.

## Delivery
- Deliver the actual MP4 when rendering is supported.
- Include editable source/project files when practical.
- State limitations plainly. Never describe a storyboard, code file, or draft as a finished exported video.
